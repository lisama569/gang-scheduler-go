# gang-scheduler-go

单进程内的本地可运行集群作业调度器：用**模拟节点 + 逻辑时钟心跳**驱动多作业并发执行，
实现 gang（整作业）调度、优先级队列、节点故障回收与进程重启恢复，
保证资源分配、故障恢复与作业状态在不同调度顺序下一致且可解释。

## 快速开始

```bash
go run ./cmd/gangscheduler   # 端到端演示
go test ./... -v             # 单测，日志含关键调度决策与资源变更依据
go test ./... -race          # 竞态检测
```

## 特性

- 作业/任务提交、资源请求、优先级与队列调度；**同一作业全部任务整体获得资源后一起启动**。
- 三类可区分拒绝原因：非法请求 `ErrInvalidRequest`、集群永远放不下
  `ErrInsufficientResources`、重复提交 `ErrDuplicateJob`（含已结束作业，不复活）。
- 节点心跳超时 → 未完成任务自动换到健康节点重调度（`Attempt+1`、进度清零从头跑）；
  已完成任务不重跑、不重计。
- **计划内维护/排空**：`DrainNode` 主动把健康节点摘出（不再收新任务、存量任务**带执行
  进度安全迁移、`Attempt` 不增长**，与故障回收严格区分），`DrainStatus` 可见剩余任务/
  资源；全部迁走后 `CompleteNodeDrain` 退役并扣减集群容量。排空/退役标记随快照持久化：
  重启后维护中节点不会被当成正常机器，**已退役节点重新注册会被 `ErrNodeRetired` 拒绝、
  容量保持收缩**，只有运维显式 `ReadmitNode` 才能重新上线。
- JSON 快照原子落盘（含作业、任务执行进度、排空/退役节点名单）；重启后未完成作业
  **带着已执行进度**继续、已结束作业不复活、资源不重复占用。
- 单把调度锁 + 合并式恢复，恢复与并发调度/提交交错时不丢作业、不超发。

规则、故障恢复语义与全部验证方法见 [`docs/design.md`](docs/design.md)。
