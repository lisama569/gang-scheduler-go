# gang-scheduler-go

单进程内的本地可运行集群作业调度器：用**模拟节点 + 逻辑时钟心跳**驱动多作业并发执行，
实现 gang（整作业）调度、优先级队列、节点故障回收、**计划内维护/节点排空（在跑任务安全在线迁移、容量收缩）**
与进程重启恢复，保证资源分配、故障恢复、维护迁移与作业状态在不同调度顺序下一致且可解释。

## 快速开始

```bash
go run ./cmd/gangscheduler   # 端到端演示（含计划内维护/排空阶段）
go test ./... -v             # 单测，日志含关键调度决策与资源变更依据
go test ./... -race          # 竞态检测
```

## 特性

- 作业/任务提交、资源请求、优先级与队列调度；**同一作业全部任务整体获得资源后一起启动**。
- 三类可区分拒绝原因：非法请求 `ErrInvalidRequest`、集群永远放不下
  `ErrInsufficientResources`、重复提交 `ErrDuplicateJob`（含已结束作业，不复活）。
- 节点心跳超时 → 未完成任务自动换到健康节点重调度；已完成任务不重跑、不重计。
- **计划内维护/下线**：`DrainNode` 把健康节点置为排空中，不再接新任务；
  在跑任务**在线迁移**到其他健康节点（不杀、不重跑、Attempt 不增、保留剩余节拍），
  全部迁走后节点才退役、容量从集群扣除；`DrainProgress` 可见剩余未迁任务数。
- **容量收缩语义**：排空发起后新提交按仅健康节点容量裁决；此前已收下、暂时放不下的作业
  继续排队（保持 Pending，不误判成功/失败、不超发）。
- JSON 快照（含节点生命周期）原子落盘；重启后排空中节点仍是排空中、退役容量持续扣除、
  迁到一半的任务不丢不重占，未完成作业继续、已结束作业不复活、资源不重复占用。
- 单把调度锁 + 合并式恢复，排空与并发调度/提交/恢复任意交错时不丢作业、不超发。

规则、故障回收与计划内维护语义、容量收缩、重启恢复及全部验证方法见 [`docs/design.md`](docs/design.md)。
